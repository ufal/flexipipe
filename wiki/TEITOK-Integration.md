## Overview

Flexipipe provides seamless integration with TEITOK XML files, allowing you to:

- **Read and write TEITOK XML** with nested `<tok>`/`<dtok>` structures
- **Update existing XML files in-place** with `--writeback` mode
- **Respect corpus-specific configurations** from `settings.xml`
- **Map attributes** between TEITOK XML and internal Document representation
- **Tokenize non-tokenized XML** files automatically
- **Process raw text** from TEITOK XML for retokenization

## Basic Usage

### Processing TEITOK XML Files

The simplest way to process a TEITOK XML file:

```bash
flexipipe --teitok --input xmlfiles/document.xml
```

This will:
- Automatically detect and load `settings.xml` from the TEITOK corpus
- Use corpus-specific attribute mappings
- Output tagged CoNLL-U by default (or TEITOK XML if `--output-format teitok` is specified)

### Enabling TEITOK Mode

Use the `--teitok` flag to enable TEITOK mode:

```bash
flexipipe --teitok --input xmlfiles/document.xml --output-format teitok
```

When `--teitok` is used, Flexipipe will:
1. Look for `tmp/cqpsettings.xml` (merged shared + local settings)
2. Fall back to `Resources/settings.xml` (standard TEITOK location)
3. Fall back to `settings.xml` in the corpus root
4. Auto-enable `--writeback` if settings are found (unless explicitly disabled)

### Specifying Settings File

To use a custom settings file:

```bash
flexipipe --teitok-settings /path/to/settings.xml --input document.xml
```

## TEITOK Settings Configuration

Flexipipe reads configuration from TEITOK's `settings.xml` file. The settings file provides:

- **Attribute mappings**: How XML attributes map to internal Document attributes
- **Default language**: Language code for NLP processing
- **CQP attributes**: Positional and structural attributes for corpus indexing
- **Preferred models**: Backend/model preferences per language
- **Flexipipe options**: Corpus-specific flags like `known-tags-only` and `use-raw-text`

### Settings File Priority

Flexipipe searches for settings files in this order:

1. **`tmp/cqpsettings.xml`** (highest priority) - Merged shared (Apache `shared_folder`) + local settings
2. **`Resources/settings.xml`** - Standard TEITOK location
3. **`settings.xml`** - Root of corpus directory

The `tmp/cqpsettings.xml` file is automatically generated by TEITOK and includes settings from Apache's shared folder merged with local project settings. Local settings override shared settings.

### Inspecting Settings

To see what settings Flexipipe will use:

```bash
flexipipe info teitok --teitok
```

Or with verbose output:

```bash
flexipipe info teitok --teitok --verbose
```

This displays:
- Settings file location
- Attribute mappings
- Default language
- CQP attributes (pattributes and sattributes)
- Preferred backend/model configurations
- Flexipipe options

### Flexipipe Section in settings.xml

Add a `<flexipipe>` section to your `settings.xml` to configure Flexipipe behavior:

```xml
<flexipipe>
  <!-- Preferred backend/model per language -->
  <models>
    <item key="en" backend="udpipe" model="english-gum-ud-2.15-241121"/>
    <item key="fr" backend="spacy" model="fr_core_news_md"/>
    <item key="es" backend="udpipe" model="spanish-gsd-ud-2.15-241121"/>
  </models>
  
  <!-- Options -->
  <options>
    <known-tags-only>true</known-tags-only>
    <use-raw-text>true</use-raw-text>
  </options>
</flexipipe>
```

Or using attributes:

```xml
<flexipipe known-tags-only="true" use-raw-text="true">
  <models>
    <item key="en" backend="udpipe" model="english-gum-ud-2.15-241121"/>
  </models>
</flexipipe>
```

**Options:**
- `known-tags-only`: Only write attributes that are defined in CQP pattributes (default: `false`)
- `use-raw-text`: Force backends to process raw text instead of pre-tokenized input (useful for retokenization, default: `false`)

## Writeback Mode

Writeback mode updates the original TEITOK XML file in-place, preserving the original structure and only updating annotation attributes.

### Enabling Writeback

Writeback is automatically enabled when:
- `--teitok` is used and `settings.xml` is found
- `--writeback` is explicitly specified

```bash
flexipipe --teitok --input xmlfiles/document.xml
```

Or explicitly:

```bash
flexipipe --input xmlfiles/document.xml --output-format teitok --writeback
```

### How Writeback Works

When writeback is enabled, Flexipipe:

1. **Preserves XML structure**: Comments, formatting, and element order are maintained
2. **Updates annotations only**: Only annotation attributes (lemma, xpos, upos, feats, head, deprel, etc.) are updated
3. **Matches by ID**: Tokens and sentences are matched by their `@id` or `@xml:id` attributes
4. **Handles MWTs**: Multi-word tokens are correctly updated with `<dtok>` children
5. **Preserves token IDs**: Original `tok/@id` values are preserved and used for matching

### Testing Writeback

To preview changes without modifying the file:

```bash
flexipipe --teitok --input xmlfiles/document.xml --test
```

Or use `--dry-run` (alias):

```bash
flexipipe --teitok --input xmlfiles/document.xml --dry-run
```

This will output the modified XML to stdout without changing the original file.

### Backup Behavior

When writeback is enabled, Flexipipe can create backups. Backups are created once per day in a `backups` folder in the execution directory, with the format:

```
backups/document-YYYYMMDD.xml
```

## Attribute Mappings

Flexipipe maps between TEITOK XML attributes and internal Document attributes. The mapping is configured in `settings.xml` via CQP pattributes.

### Standard Mappings

Default attribute mappings (if not specified in settings):

| Internal Attribute | XML Attributes (priority order) |
|-------------------|--------------------------------|
| `xpos` | `xpos`, `msd`, `pos` |
| `reg` | `reg`, `nform` |
| `expan` | `expan`, `fform` |
| `lemma` | `lemma` |
| `tokid` | `id`, `xml:id` |

### CQP Pattributes

CQP pattributes in `settings.xml` define which XML attributes are used for token-level features:

```xml
<cqp>
  <pattributes>
    <item key="pos"/>      <!-- Maps to xpos -->
    <item key="lemma"/>    <!-- Maps to lemma -->
    <item key="reg"/>      <!-- Maps to reg -->
  </pattributes>
</cqp>
```

### Explicit Mappings

You can explicitly map XML attributes to internal attributes using the `flexipipe` attribute:

```xml
<cqp>
  <pattributes>
    <item key="custom_pos" flexipipe="xpos"/>  <!-- custom_pos → xpos -->
    <item key="norm" flexipipe="reg"/>         <!-- norm → reg -->
  </pattributes>
</cqp>
```

### Known Tags Only Mode

When `known-tags-only="true"` is set in the `<flexipipe>` section (or via `--known-tags-only`), only attributes defined in CQP pattributes are written to the XML. This helps standardize tags across a corpus.

## Tokenization Mode

For TEITOK XML files without `<tok>` elements, use tokenization mode:

```bash
flexipipe --teitok --input xmlfiles/raw_text.xml --tokenize
```

This will:
1. Extract plain text from the XML (using XPath)
2. Tokenize the text
3. Insert `<tok>` elements into the XML structure
4. Preserve the original XML structure and markup

### Customizing Text Extraction

By default, text is extracted from `.//text` elements. To customize:

```bash
flexipipe --teitok --input document.xml --tokenize --textnode ".//body"
```

To include `<note>` elements:

```bash
flexipipe --teitok --input document.xml --tokenize --textnotes
```

### Restricting to a subset of the text (e.g. answers only)

When your TEI marks different parts (e.g. question vs. student answer with `@src="question"` and `@src="answer"`), you can tokenize and annotate only the parts you need by using an XPath that selects those elements.

Example: only tokenize/annotate content inside elements with `@src="answer"` (student answers), and leave question text untouched:

```bash
flexipipe --teitok --input document.xml --tokenize --textnode ".//*[@src='answer']" --writeback
```

The same `--textnode` value is used for both extracting plain text for the backend and for inserting `<s>`/`<tok>` back into the XML, so only the matched elements receive tokens and annotations. With `--writeback`, the file is updated in place; only the answer portions are tokenized.

For namespaced TEI (e.g. default `xmlns="http://www.tei-c.org/ns/1.0"`), the code applies namespace-agnostic matching where possible (`.//` is treated as “any namespace”). If an XPath without `.//` (e.g. `//*[@src='answer']`) does not match, try `.//*[@src='answer']`.

## Raw Text Processing

When using `--use-raw-text` (or `use-raw-text="true"` in settings), Flexipipe sends raw text to the backend instead of pre-tokenized input. This is useful for:

- **Retokenization**: Let the backend retokenize (e.g., UDPipe can split contractions)
- **Better segmentation**: Backends may have better sentence segmentation
- **Token splitting**: Backends can create multi-word tokens (MWTs) from raw text

### Example: Retokenization with UDPipe

```bash
flexipipe --teitok --input document.xml --use-raw-text --backend udpipe --language es
```

This will:
1. Extract text from existing `<tok>` elements
2. Send raw text to UDPipe
3. UDPipe retokenizes and may create new MWTs (e.g., "al" → "a" + "el")
4. Update the XML with new tokenization and annotations

### Multi-Word Tokens (MWTs)

When backends create MWTs from raw text, Flexipipe correctly handles them:

- Parent `<tok>` element gets the MWT form (e.g., "al")
- `<dtok>` children are created for each part (e.g., "a", "el")
- Dtok IDs are generated as `{parent_id}.{index}` (e.g., `w-30.1`, `w-30.2`)
- Head and deprel attributes are set on `<dtok>` elements
- Duplicate IDs are automatically resolved

## Advanced Features

### Language Resolution

Language is determined in this priority order:

1. **CLI `--language`** (highest priority)
2. **Document metadata** (from `teiHeader`)
3. **TEITOK settings** (`/defaults/@lang`)
4. **Language detection** (if enabled)

### Preferred Models

Configure preferred backend/model pairs in `settings.xml`:

```xml
<flexipipe>
  <models>
    <item key="en" backend="udpipe" model="english-gum-ud-2.15-241121"/>
    <item key="fr" backend="spacy" model="fr_core_news_md"/>
  </models>
</flexipipe>
```

Flexipipe will automatically use these preferences when processing files in the specified languages, unless overridden by CLI arguments.

### Task Selection

Control which NLP tasks are performed:

```bash
flexipipe --teitok --input document.xml --tasks tokenize,tag,parse
```

Available tasks: `tokenize`, `segment`, `lemmatize`, `tag`, `parse`, `normalize`, `ner`

When `--writeback` is enabled, a default set of tasks is automatically applied to ensure proper tagging.

### Output Format

By default, when `--teitok` is used, output format is `teitok`. To change:

```bash
flexipipe --teitok --input document.xml --output-format conllu
```

### Batch processing (folder of XML files)

You can pass a **directory** as `--input`; flexipipe will process every file matching the glob pattern (default `*.xml`) in one run. The backend is loaded once and reused for all files, which is much faster than starting flexipipe per file.

```bash
flexipipe --teitok --input /path/to/xmlfiles --tokenize --textnode ".//*[@src='answer']" --writeback
```

- By default, only `*.xml` files in the directory are processed. Use `--input-glob "*.xml"` (default) or another pattern (e.g. `--input-glob "exam-*.xml"`).
- If you pass `--output` and it is a directory, each input file is written to `output_dir/<same filename>`.
- With `--writeback` and directory input, each file is updated in place (no need to set `--output`).

To run only tokenization (no tagging/parsing):

```bash
flexipipe --teitok --input /path/to/xmlfiles --tokenize --tasks tokenize,segment --textnode ".//*[@src='answer']" --writeback
```

For annotation-only (files already tokenized), omit `--tokenize` and use default tasks or e.g. `--tasks tag,lemma,parse`.

## Examples

### Example 1: Basic Tagging with Writeback

```bash
flexipipe --teitok --input xmlfiles/document.xml
```

This will:
- Load settings from `tmp/cqpsettings.xml` or `Resources/settings.xml`
- Use preferred backend/model from settings
- Tag the document
- Update the XML file in-place

### Example 2: Retokenization with UDPipe

```bash
flexipipe --teitok --input document.xml --use-raw-text --backend udpipe --language es
```

This will:
- Extract text from existing tokens
- Send raw text to UDPipe for retokenization
- Update XML with new tokenization and annotations

### Example 3: Tokenizing Raw XML

```bash
flexipipe --teitok --input raw_text.xml --tokenize --backend udpipe --language en
```

This will:
- Extract plain text from XML
- Tokenize with UDPipe
- Insert `<tok>` elements into the XML

### Example 4: Preview Changes

```bash
flexipipe --teitok --input document.xml --test
```

This will:
- Process the document
- Output modified XML to stdout
- Not modify the original file

### Example 5: Answer-only tokenization and batch (e.g. escola corpus)

For a corpus where question text and student answers are marked with `@src="question"` and `@src="answer"`, tokenize and annotate only the answer parts. Use a **directory** as input so all files are processed in one run (backend loaded once):

```bash
XMLDIR="../easycorp/teitok/escola/xmlfiles"
flexipipe --teitok --input "$XMLDIR" --tokenize --textnode ".//*[@src='answer']" --writeback
```

To run only tokenization first (no tagging/parsing):

```bash
flexipipe --teitok --input "$XMLDIR" --tokenize --tasks tokenize,segment --textnode ".//*[@src='answer']" --writeback
```

Then run annotation (tag, lemma, parse) on the same directory; omit `--tokenize` so existing tokens are annotated.

### Example 6: Custom Settings

```bash
flexipipe --teitok-settings /path/to/custom-settings.xml --input document.xml
```

This will:
- Use the specified settings file
- Apply custom attribute mappings
- Use preferred models from custom settings

## Troubleshooting

### Settings Not Found

If Flexipipe can't find `settings.xml`:

1. Check that you're running from a TEITOK corpus directory
2. Verify `Resources/settings.xml` exists
3. Use `--teitok-settings` to specify the path explicitly
4. Check that `tmp/cqpsettings.xml` exists (if using Apache shared settings)

### Attribute Mappings Not Applied

If attribute mappings aren't working:

1. Check CQP pattributes in `settings.xml`
2. Use `flexipipe info teitok --teitok --verbose` to see parsed mappings
3. Verify explicit `flexipipe="..."` attributes are set correctly
4. Check that `--known-tags-only` isn't preventing attributes from being written

### Writeback Not Working

If writeback isn't updating the file:

1. Check file permissions (writeback requires write access)
2. Verify the file has `<tok>` elements (use `--tokenize` if needed)
3. Check that token IDs (`@id` or `@xml:id`) are present
4. Use `--test` to preview changes first
5. Check for error messages in verbose mode: `--verbose`

### Duplicate Token IDs

If you see duplicate token IDs:

- Flexipipe automatically resolves duplicate IDs by appending suffixes
- Check that original XML doesn't have duplicate IDs
- Use `--verbose` to see which IDs are being modified

### MWT Issues

If multi-word tokens aren't handled correctly:

1. Ensure `--use-raw-text` is used if you want retokenization
2. Check that backend supports MWT creation (UDPipe, SpaCy, etc.)
3. Verify dtok IDs are in format `w-{parent_id}.{index}`
4. Check that head/deprel attributes are set on dtok elements

### Performance Issues

If processing is slow:

1. Use `--use-raw-text` for faster backend processing
2. Check that settings.xml parsing isn't slow (use `--teitok-settings` to cache)
3. Use `--verbose` to see where time is spent
4. Consider processing files in batches

## One-pass UDPipe + NameTag pipeline

For untokenized TEITOK XML, you can run morphosyntax and NER in a single `flexipipe process` invocation. UDPipe tokenizes and tags; NameTag runs afterward on the pretokenized document when `--ner-backend nametag` is set:

```bash
flexipipe process --teitok --input doc.xml --tokenize \
  --backend udpipe --language cs --model czech-pdt-ud-2.15-241121 \
  --ner-backend nametag --nametag-model nametag3-multilingual-conll-250203 \
  --tasks segment,tokenize,lemmatize,tag,parse,ner --writeback
```

Use `--output other.xml` to write a copy while keeping the source file unchanged (when not using in-place writeback).

## Line-break rejoin (historic typography)

Hyphenated words split across `<lb break="no"/>` (and similar cases with `<pc>-</pc>`) are merged for NLP while preserving inner XML on insert. This is on by default; disable with `--no-rejoin-linebreaks`.

Example display text `wšewědau-cností` with a break-no line break becomes one NLP token `wšewědaucností`; writeback sets `@form` to the merged surface form but keeps the original markup inside `<tok>`.

**Gap preservation:** Characters removed only for NLP (hyphens, whitespace around breaks, markup between word parts) stay in the TEI XML. They are tracked in rejoin metadata and are not required to match UDPipe sentence strings during writeback. Blocks are matched by global NLP offsets, not by comparing display plaintext to backend text.

**Skipping blocks** should be rare (empty blocks or unrecoverable token alignment). Use `--verbose` to see block-map and anchoring statistics.

### Dry-run validation (PressMint-scale XML)

```bash
python3 -m flexipipe process --teitok --test \
  --input backups/PressMint-CZ_1848-04-05-f2413420-c8eb-11e9-bfd1-5ef3fc9bb22f-20260521.xml \
  --tokenize --backend udpipe --language cs \
  --model czech-pdt-ud-2.15-241121 \
  --tasks segment,tokenize,lemmatize,tag,parse \
  --writeback --verbose
```

Expect a log line like `Block map: N/M blocks, sentences anchored P/Q` with most blocks mapped, and few or no “Could not assign sentences” warnings.

## NER as `<name>` wrappers

When NER is requested, entities are written as TEITOK `<name type="...">` elements wrapping the relevant `<tok>` nodes (not only token-level attributes). This applies on standoff insert (`--tokenize`) and on in-place `update_teitok` writeback.

## flexiconv TEI P5 export

After flexipipe produces TEITOK XML, `flexiconv -f teitok -t tei` builds a minimal TEI P5 view (`<w>`, `<s>`). It does not preserve full TEITOK structure, `<name>` spans, or all attributes—use TEITOK XML as the archival format when those matter.
